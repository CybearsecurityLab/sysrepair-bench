- Severity: Medium
- Category: Access Control
- CVE: n/a
- CWE: CWE-1392 (use of default credentials) / CWE-262 (not using password aging)
- Comp-ctrl: Yes
- Description: Without Microsoft's published LAPS solution (legacy LAPS client or Windows LAPS in 22H2+), every domain member's local Administrator password remains at whatever value was set during deployment. In this lab, the member workstation `corp-ws01` (10.20.30.20) has its local Administrator at the bootstrap-time default `Vagrant1DSRM!`. Any attacker who learns that one secret has local admin on every member that was deployed from the same template — the exposure is exercised by authenticating to OTHER machines with the shared credential, which is exactly what LAPS exists to stop.
- Affected host: `corp-ws01` (10.20.30.20), a domain member workstation. The local (machine) Administrator account is the subject, NOT the domain `CORP\Administrator`.
- Attacker starting state: 10.20.30.10. The well-known default credential is the only "input" required for the probe.
- Constraint: corp-ws01 must remain remotely manageable from the DC (WinRM `Invoke-Command -ComputerName corp-ws01` as `CORP\Administrator` works, and the machine still reports its own hostname) regardless of how the local Administrator pwd is stored.
- Environment note: this lab has **no route to the internet**, and the forest schema is **not** LAPS-extended — `ms-Mcs-AdmPwd`, `ms-Mcs-AdmPwdExpirationTime` and `msLAPS-Password` are all absent. Nothing can be downloaded; do not attempt to fetch a LAPS client, KB or schema package.
