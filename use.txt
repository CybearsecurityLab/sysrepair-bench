SysRepair -- Intended Use and Limitations
=========================================

INTENDED USE

SysRepair measures whether an autonomous agent can remediate a vulnerability on
a running system without breaking the services that system provides. It is
intended for:

  - benchmarking agentic solvers on defensive system-administration tasks
  - comparing solver architectures under a fixed, dual-objective oracle
  - research on neural-symbolic planning for change-controlled environments

Every scenario is a self-contained container. The vulnerabilities are real
configuration and version weaknesses, and the exploit checks are genuine, but
they run only against the disposable target inside the scenario's own network
namespace.

LIMITATIONS

Scope. Success is judged by an execution oracle: a canonical exploit check plus
per-service availability checks. An agent that satisfies both is scored correct
even if a human operator would consider the fix inelegant, over-broad, or
unmaintainable. The oracle does not measure maintainability, style, or
adherence to site policy.

Not a security product. A passing score means the scripted exploit no longer
succeeds and the declared services still answer. It is not a claim that the host
is secure against an adaptive adversary, and nothing here should be used as
evidence that a production system has been remediated.

Non-determinism. Solvers are stochastic. Cells are replicated across epochs and
reported at pass@K precisely because a single run is not reproducible in the
bitwise sense. Reproducing a published cell means recovering the reported
statistic within its interval, not reproducing a specific trajectory.

Model availability. Hosted-model results depend on provider endpoints that
change without notice. A provider may deprecate a checkpoint, alter default
sampling, or route to different hardware. Results obtained after publication may
therefore differ from the published cells through no fault of the harness. This
is why the full evaluation logs ship with the artifact.

Cost and hardware. Reproducing the complete grid at paper scale requires
substantial GPU time and paid API calls. Every claim ships a scaled-down mode
for this reason.

DUAL-USE CONSIDERATION

The corpus contains working exploit checks for known vulnerabilities, used to
verify that remediation succeeded. They target only the disposable container
supplied with each scenario, they are drawn from public sources already
documented in CVE databases and public practice material, and they exist to
score defence rather than to enable offence. We judged that withholding them
would make the benchmark unverifiable while withholding nothing from an
adversary. Per-suite provenance is recorded in artifact/scenarios/PROVENANCE.md.
